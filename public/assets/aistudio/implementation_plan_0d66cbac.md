# HOP-Claw 2.0 보안 보완 Implementation Plan

> **실행자 지침:** 이 문서의 체크박스를 순서대로 처리한다. 각 작업은 실패 테스트 작성 → 실패 확인 → 최소 변경 → 통과 확인 → 커밋 순서로 진행한다. 구현 후에는 독립적인 보안 검토와 전체 회귀 검증을 거친다. 이 계획은 구현 승인 전 검토용이며, 체크박스는 실제 구현이 완료된 뒤에만 표시한다.

**Goal:** 2026-11-20 보안 검토에서 확인한 HOP-Claw 2.0의 실행 경계, 문서 편집 정책, 파일 처리, 개인정보 보호 및 CI 공백을 단계적으로 보완한다.

**Architecture:** 네트워크 요청, 파일 경로, 외부 명령, 문서 편집 연산, 압축 해제, CI 권한을 각각 신뢰 경계로 다룬다. 편집 정책은 모든 편집 진입점에서 우회할 수 없어야 하며, 외부 CLI에는 사용자가 허용한 데이터만 전달되어야 한다. Hook, Loop, CLI 어댑터 중 어느 한 구현 패턴을 선결정하지 않고, 기존 에이전트 동작과 호환성을 확인한 뒤 모든 경로를 막는 최소 변경을 선택한다.

**Tech Stack:** React 19, TypeScript, Vite 6, Tauri 2, Rust/Cargo, Node.js, fflate, Vitest, GitHub Actions.

**Spec:** 2026-11-20 보안 검토 결과. 기준 저장소는 `inter-schema/hwpcolab_2.0_develop`, 기준 브랜치는 `main`, 기준 커밋은 `3fdb3bd58b77b1d6d1e3157e5d6a97e25d3807fc`이다. 별도 설계 문서는 없으며, 이 계획이 검토 결과를 구현 가능한 단일 작업 기준으로 정리한다.

## 2. 전역 제약

1. 원본 HWP/HWPX 문서의 저장·복구 동작과 기존 Diff 검토 흐름을 보안 개선만을 이유로 임의 변경하지 않는다.
2. 개발 서버의 기본 바인딩은 루프백으로 제한한다. 네트워크 공개가 꼭 필요한 경우에만 별도 설정과 인증을 갖춘 명시적 선택 경로를 제공한다.
3. 사용자가 터미널에 직접 입력해 실행하는 기능과 파일 선택값을 명령 문자열에 끼워 넣는 동작을 구분한다. 전자는 명시적 사용자 동작으로 유지할 수 있지만, 후자는 실행 파일과 인자 배열로 분리한다.
4. 편집 정책은 UI 또는 CLI wrapper에서만 검사해서는 안 된다. 실제 문서 변경이 실행되는 모든 경로에서 동일한 정책 결과를 강제한다.
5. PII 마스킹이 프롬프트 문자열만 처리하는 경우, 문서 파일이나 작성 메모리의 직접 읽기까지 보호한다고 표시하지 않는다.
6. 압축 파일은 압축 해제 전에 메타데이터를 검사하고, 압축 해제 중에도 크기·파일 수 한도를 강제한다.
7. 보안 테스트에는 합성 문서와 임시 파일만 사용한다. 실제 사용자 문서, API 키, 운영 서버를 대상으로 공격 재현을 수행하지 않는다.
8. 저장소에 새 보안 스캐너를 추가할 때는 도구 버전, 실행 명령, 대상 범위, 제외 항목을 CI 로그에서 확인할 수 있게 한다. 실제 실행하지 않은 스캐너는 통과했다고 기록하지 않는다.

### Task 1: 개발 서버 API와 정적 파일 경로 보호

**기간:** T1 · 2026-11-25–2026-11-27  
**우선순위:** P0

**대상 파일**
- `vite.config.ts`

**작업 1-A · 개발 서버 노출 제한**
- [ ] Vite 서버의 기본 host를 `127.0.0.1` 또는 동등한 루프백 전용 설정으로 변경한다.
- [ ] `/__hop_claw_api/` 요청에 대해 Host와 Origin을 검증하고, 신뢰하지 않는 출처의 요청은 실행 전에 거부한다.
- [ ] 셸 실행 및 파일 읽기·쓰기 API는 신뢰된 로컬 UI의 사용자 동작에서만 도달할 수 있도록 보호한다. 필요한 경우 세션 범위의 예측 불가능한 토큰을 추가한다.
- [ ] 네트워크 공개 모드를 추가해야 한다면 기본값과 분리하고, 명시적 설정·인증·경고를 모두 요구한다.
- [ ] 오류 응답이나 로그에 환경변수, 명령 전체의 비밀 인자, 민감한 파일 내용이 포함되지 않는지 확인한다.

**작업 1-B · /fonts 및 /samples 경로 제한**
- [ ] URL 경로를 정규화한 뒤 실제 파일 경로를 계산한다.
- [ ] 정규화된 경로가 각각의 허용 루트 내부에 있는지 검사한다. 심볼릭 링크가 허용 루트 밖으로 향하는 경우도 차단한다.
- [ ] 잘못된 퍼센트 인코딩, 이중 인코딩, 슬래시·역슬래시 혼용, 드라이브 경로, UNC 경로를 거부한다.
- [ ] 허용 파일 유형과 정적 디렉터리의 기존 접근 기능을 유지한다.

**필수 회귀 테스트**
- [ ] 루프백의 정상 요청은 허용하고, 비루프백 Host와 잘못된 Origin 요청은 거부한다.
- [ ] `/fonts/`와 `/samples/`에서 `..`, 인코딩된 `..`, 이중 인코딩, 심볼릭 링크 경로 탈출을 차단한다.
- [ ] 정상 폰트 및 샘플 파일 요청은 기존과 같이 성공한다.
- [ ] 거부된 요청에서 셸 명령이나 파일 I/O가 실행되지 않았음을 확인한다.

**완료 기준:** 개발용 API가 기본적으로 네트워크에 노출되지 않고, 두 정적 경로가 허용 루트 밖의 파일을 반환하지 않는다.
