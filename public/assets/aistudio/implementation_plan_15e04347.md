# HOP-Claw v2 전면 개편 계획 — IDE형 에이전트 CLI 기반 HWP/HWPX 스튜디오

기존의 내장 LLM 채팅 사이드바와 유기된 `hop-host` 래퍼를 전면 폐기하고, 최신 `rhwp-studio` 문서 편집 코어와 우측/하단 도킹형 내장 에이전트 CLI 터미널을 결합한 IDE 스타일의 HWP/HWPX 협업 스튜디오로 재설계합니다. 문서 편집·중첩표·레이아웃 검증·참고자료 추출 기능은 외부 에이전트 CLI가 표준 규격으로 호출할 수 있는 스킬 패키지로 이전하고, 작성 메모리와 개인정보 보호(PII)는 앱 UI에 유지하며, 전체 프로젝트는 GNU GPL v3.0 라이선스를 준수합니다.

---

## 사용자 검토 및 확정 의사결정

> [!IMPORTANT]
> 인터뷰와 추가 요청을 통해 확정된 핵심 설계 방향입니다. 아래 내용을 확인하신 뒤 승인해 주시면 단계별 개편 구현을 시작합니다.

- **확정 1 — 에이전트 CLI 연동 방식**: 좌측 AI 채팅 사이드바와 내장 LLM API 프로바이더 계층을 제거하고, **우측 또는 하단으로 도킹 전환이 가능한 내장 에이전트 CLI 터미널 패널** 전용 워크스페이스를 신설합니다. (Claude Code, Gemini CLI, Codex, 사용자 지정 셸/CLI 프리셋 지원)
- **확정 2 — 기능 스킬화 vs 앱 UI 유지 범위**:
  - **스킬(`SKILL.md` + 독립 CLI 도구)로 이전**: HWP/HWPX 구조 편집, HWPX 중첩 표 삽입, 레이아웃 실측·넘침 검증, 정책 가드, 공문서 표준 서식 교정, 다중 참고자료(DOCX/XLSX/PDF/HWP/TXT) 텍스트·표 추출.
  - **앱 UI에 유지**: 작성 선호사항 메모리(Writing Memory) 관리·비교·활성화 UI 및 개인정보 자동 마스킹/전송 제외 영역(PII) 관리 UI.
- **확정 3 — 변경 검토 및 반영 방식**: 에이전트 CLI가 스테이징 파일을 수정하면 변경을 자동 감지하고, **최신 `rhwp-studio` 문서 비교 엔진으로 기준본과 수정본을 시각적 Diff로 대조**한 뒤 사용자가 수락(에디터 반영) 또는 반려(롤백)하도록 구성합니다.
- **확정 4 — 에디터 코어 및 중첩 표 생성 UX**: 유기된 기존 `hop-host`를 폐기하고 **최신 `rhwp-studio`를 전면 채택**하며 IDE 헤더·상태바와 결합합니다. 별도의 중첩표 전용 UI를 두지 않고, **기존 `rhwp-studio`의 `[표 만들기]` 버튼과 그리드/상세 대화상자가 표 셀 내부에 커서가 있을 때도 활성화되어 중첩 표를 직접 생성**하도록 개선합니다.
- **확정 5 — 라이선스**: 전면 개편된 앱과 신설 스킬 패키지 모두 **GNU General Public License v3.0 (`GPL-3.0-or-later`)**을 적용하고, 최신 서드파티 라이선스 고지를 반영합니다.

## 1. 개요 및 핵심 컨셉

- **무엇을 하는 앱인가**: 사용자가 로컬에 설치해 쓰는 범용 에이전트 CLI(Claude Code, Gemini CLI, Codex 등)를 HWP/HWPX 전용 에디터 옆(우측 또는 하단)에 IDE처럼 띄워두고, 표준 스킬을 통해 문서를 읽고·편집하고·레이아웃을 실측 검증한 결과를 시각적 Diff로 안전하게 검토·반영하는 데스크톱/웹 문서 IDE입니다.
- **타깃 사용자 및 맥락**: 공공기관·교육기관·기업 실무자 및 개발자 중 이미 개인/조직용 에이전트 CLI 구독이나 로컬 코딩 에이전트를 사용하고 있으며, 별도 API 키 이중 관리 없이 기존 에이전트 워크플로로 한글 공문서·보고서·과정안을 정밀하게 편집하고자 하는 사용자.
- **핵심 가치**:
  1. **에이전트 종속성 탈피**: 앱 내부에 LLM 프로바이더와 에이전트 루프를 떠안지 않고, 빠르게 진화하는 외부 에이전트 CLI를 그대로 IDE 내부에 불러와 활용합니다.
  2. **자산의 재사용(스킬화)**: 기존에 검증된 HWP 편집, 중첩표 생성, 레이아웃 넘침 계측, 참고자료 파싱 역량을 독립적인 `SKILL.md` + CLI 도구로 표준화하여 어떤 CLI 에이전트에서도 동일하게 작동합니다.
  3. **신뢰할 수 있는 최신 편집기 & 안전한 검토**: 최신 `rhwp-studio`의 표/중첩표 렌더링·편집·비교 엔진을 직접 사용하고, 스테이징 파일 감시 + PII 가명화/복원 + 시각적 Diff 수락/반려로 문서 손상을 원천 차단합니다.

## 2. 사용자 경험 및 시각 디자인

### 주요 사용자 플로우

1. **문서 열기 및 스테이징 세션 초기화**:
   - 사용자가 로컬 HWP/HWPX 문서를 열거나 새 빈 문서를 생성하면, 원본과 분리된 **스테이징 작업 사본**과 **기준 스냅샷(Baseline)**이 생성되고 최신 `rhwp-studio` 캔버스에 문서가 렌더링됩니다.
   - IDE 상단 헤더에는 문서명·저장 상태·열기/저장/되돌리기·작성 메모리·PII 보호·CLI 터미널 토글·라이선스 진입점이 깔끔하게 배치됩니다.
2. **직접 편집 및 통합 `[표 만들기]` 중첩 표 생성**:
   - 사용자는 최신 `rhwp-studio`의 메뉴바·아이콘 툴바·서식 툴바·눈금자를 이용해 문서를 직접 편집합니다.
   - 커서가 **본문**에 있을 때 `[표 만들기]`를 클릭하면 일반 표가 생성되고, 커서가 **표 셀 내부**에 있을 때 동일한 `[표 만들기]` 버튼을 클릭해도 비활성화되지 않고 동일한 그리드 피커/상세 대화상자가 열려 해당 셀 안에 **중첩 표**를 삽입합니다.
   - 레거시 `.hwp` 문서의 표 안에서 중첩 표 생성을 시도하면 차단 알림창(`alert`) 대신 비차단 인앱 토스트로 HWPX 형식 지원 안내와 HWPX 저장 유도 액션을 표시합니다.
3. **우측/하단 도킹 내장 에이전트 CLI 실행**:
   - 사용자가 터미널 패널 토글(또는 단축키)을 열면 우측 또는 하단에 도킹된 멀티탭 터미널이 나타납니다.
   - 사용자는 상단 탭에서 프리셋(`Claude Code`, `Gemini CLI`, `Codex`, `로컬 셸`)을 선택하거나 커스텀 실행 명령을 입력해 세션을 시작합니다.
   - 터미널은 자동으로 현재 문서의 스테이징 경로, 내장 스킬 디렉터리 경로, 활성화된 작성 메모리 컨텍스트 파일 경로를 환경 변수 및 워크스페이스 지침으로 주입받아 별도 경로 복사 없이 바로 작업을 시작할 수 있습니다.
   - 필요 시 `[현재 선택 영역 전달]`, `[작성 메모리 지침 주입]`, `[참고자료 폴더 열기]` 퀵 액션으로 현재 에디터 문맥을 터미널에 즉시 보낼 수 있습니다.
4. **PII 보호 및 작성 메모리 연동**:
   - 민감 문서 작업 시 헤더의 PII 보호 토글을 켜면, 스테이징 파일 텍스트의 개인정보 패턴과 사용자가 지정한 제외 영역을 가명 토큰으로 치환한 작업본을 CLI에 넘기고, 반영 시 원본 값으로 복원합니다.
   - 작성 선호사항 모달에서 여러 문체·서식 규칙을 선택/활성화하면, 활성 규칙이 워크스페이스 컨텍스트 파일로 자동 동기화되어 에이전트 CLI가 즉시 참고할 수 있습니다.
5. **CLI 수정 자동 감지 및 `rhwp-studio` 비교 엔진 Diff 검토**:
   - 에이전트 CLI가 스킬을 호출해 스테이징 파일을 수정하면 파일 변경 감지가 즉시 트리거됩니다.
   - 앱은 최신 `rhwp-studio`의 문서 비교 엔진을 실행해 **기준 스냅샷 vs CLI 수정본**의 변경 목록(문단 추가/수정/삭제, 표 행·열 및 셀별 텍스트 변경, 도형/이미지 변경)을 계산합니다.
   - 에디터 상단에 검토 배너와 비교 패널이 열려 변경 항목별 이전/이후 내용 비교, 해당 위치 점프, `[변경 수락하여 반영]` 또는 `[반려하고 되돌리기]`를 원클릭으로 처리할 수 있습니다.

### 시각 아이덴티티 및 테마

- **미학적 방향**: 집중력 있는 개발자 문서 IDE(Developer Document Studio) — 불필요한 장식이나 과장된 AI 그래디언트 없이, 종이 문서(에디터 캔버스)와 정밀한 작업 도구(툴바·터미널·Diff 패널)가 명확히 구분되는 절제된 실무형 인터페이스.
- **색상 팔레트 및 60-30-10 배분**:
  - **라이트 / 다크 듀얼 테마 동기화**: `rhwp-studio`의 테마 모드(`system` / `light` / `dark`)와 IDE 셸(헤더, 터미널 패널, 모달, 상태바)이 단일 테마 토큰으로 완전 동기화됩니다.
  - **60% 중립 캔버스**: 에디터 배경 및 작업 영역 (`#F3F4F6` 라이트 / `#0F172A` 다크).
  - **30% 구조 표면**: 헤더, 터미널 크롬, Diff 리스트, 모달 표면 (`#FFFFFF` / `#1E293B` + `1px` 헤어라인 보더).
  - **10% 의도 강조 액센트**: 활성 탭, 수락 버튼, 포커스 링에만 절제된 블루/틸 액센트(`#2563EB` / `#0D9488`)를 사용하고, Diff 추가(`#16A34A`), 삭제(`#DC2626`), 경고(`#D97706`)는 반드시 텍스트 라벨/기호(`+`, `-`, `~`)와 병행 표기합니다.
- **타이포그래피 및 위계**:
  - **UI 본문 및 제목**: `Pretendard`와 `Plus Jakarta Sans` 조합 (단일 행 컨트롤 `whitespace-nowrap`, 최대 2개 굵기 400/600 유지).
  - **터미널·좌표·수치**: `JetBrains Mono` / `D2Coding` + `tabular-nums` 적용으로 페이지 번호, 행·열 좌표, 변경 건수, 터미널 출력의 수직 정렬을 유지합니다.
- **안티-슬롭 및 레이아웃 규율**:
  - 정적 메타데이터(파일 형식, 페이지 수, 변경 건수, GPL v3.0 표기)는 둥근 알약 배지(pill)를 남발하지 않고 구분자(`·`)가 있는 깔끔한 텍스트로 표기합니다.
  - 장식용 펄스 점, 가짜 시스템 레이턴시 티커, 두꺼운 좌측 액센트 바, 중첩 카드 구조를 배제하고 1px 헤어라인과 여백으로 영역을 분리합니다.
  - 좌측 사이드바 영역을 완전히 제거해 1440px 데스크톱 기준 문서 캔버스 가시 폭을 극대화하고, 에이전트 CLI 터미널은 우측(기본 420px, 드래그 리사이즈) 또는 하단(기본 280px, 드래그 리사이즈) 도킹으로 전환합니다.

### 인터랙션 피드백 및 상태 설계

- **도킹 및 리사이즈**: 드래그 핸들 조작 시 캔버스 리사이즈와 `rhwp-studio` 뷰포트 재계산이 지연 없이 부드럽게 반영됩니다.
- **비차단 피드백**: 모든 안내·경고(HWPX 전용 중첩표 안내, 스테이징 변경 감지, 저장 완료, CLI 실행 오류)는 브라우저 기본 `alert` 대신 인앱 토스트와 상태바로 일관되게 전달됩니다.
- **완전한 상태 커버리지**: 빈 문서 상태, CLI 미설치/실행 실패 복구 안내(설치 명령/경로 설정), Diff 계산 중 로딩 인디케이터, 변경 없음 상태, PII 마스킹 활성 경고를 빠짐없이 제공합니다.

## 3. 주요 제품 의사결정 및 트레이드오프

### 결정 1: 내장 LLM 오케스트레이터 제거 및 내장 에이전트 CLI 터미널 전환
- **선택한 방식**: 기존 내장 API 프로바이더(BAZE/Claude/OpenAI/Gemini/Ollama)와 자체 에이전트 루프(Legacy/v2)를 앱 코어에서 제거하고, 사용자가 로컬에 보유한 에이전트 CLI를 우측/하단 도킹 터미널 패널에서 실행하는 구조로 전환합니다.
- **이유**: 에이전트 CLI 도구들이 자체적으로 최신 모델·도구 호출·컨텍스트 압축·권한 관리를 빠르게 발전시키고 있어, 앱이 개별 LLM API와 에이전트 루프를 유지보수하는 비용보다 IDE형 터미널 호스팅 + 표준 스킬 제공이 훨씬 지속 가능하고 유연합니다.
- **검토한 대안**: 기존 내장 채팅 사이드바와 터미널을 병행 유지하는 안은 UI 복잡도와 유지보수 부담이 이중화되므로 제외했습니다.

### 결정 2: 기존 기능의 선별적 스킬 이전 vs 앱 UI 유지
- **선택한 방식**:
  - **스킬 이전**: `hwp-editor` 스킬(문서 추출, 문단/셀/서식 편집, HWPX 중첩표 삽입, 레이아웃 넘침 실측 `inspect-layout`, 정책 가드 `lint-ops`, 공문서 서식 규칙, OWPML 언팩/팩/검증)과 `reference-extract` 스킬(DOCX/XLSX/PDF/HWP/TXT 안전 파싱)로 모듈화합니다.
  - **앱 UI 유지**: 작성 선호사항 메모리와 개인정보 마스킹/제외 영역 관리는 사용자가 문서를 보며 직관적으로 토글·편집·검토해야 하는 휴먼-인-더-루프 제어면이므로 앱 UI에 유지하고, 활성 상태를 워크스페이스 컨텍스트로 CLI에 자동 연동합니다.
- **이유**: 편집·파싱·실측은 CLI가 반복 호출하는 자동화 도구 성격이 강해 스킬로 분리할 때 가치가 극대화되며, 작성 메모리(스타일 관리)와 PII 보호(보안 통제)는 시각적 UI에서 사용자가 명시적으로 관리할 때 안전성이 높습니다.
- **검토한 대안**: 작성 메모리와 PII까지 모두 CLI 텍스트 설정으로 넘기는 안은 일반 실무자의 사용성과 개인정보 실수 방지력이 떨어져 제외했습니다.

### 결정 3: 유기된 `hop-host` 폐기 및 최신 `rhwp-studio` 직접 호스팅 + `[표 만들기]` 통합
- **선택한 방식**: 구형 `hop-host` 포크 오버라이드 층을 제거하고 최신 `rhwp-studio` 코어를 직접 임베드하되, 최소한의 확장 훅(데스크톱 파일/폰트 브리지, 스테이징 동기화, 그리고 `table:create` 중첩 표 지원 확장)만 얇게 결합합니다.
- **이유**: 최신 `rhwp-studio`에는 중첩 표 셀 포인터·텍스트 선택·복사, 고도화된 문서 비교 엔진, CanvasKit/Canvas2D 렌더러, 자동저장 복구 등이 이미 구현되어 있습니다. 구형 `hop-host`를 유지하면 업스트림 개선을 흡수하기 어렵습니다.
- **중첩 표 UX 통합 근거**: `table:create`의 `canExecute`에서 `!ctx.inTable` 제약을 해제하고 커서 위치(`pos.parentParaIndex !== undefined`)를 분기하여 본문이면 기본 WASM 표 생성, 셀 내부이면 HWPX 중첩 표 삽입 파이프라인을 실행하도록 통합하면 별도 버튼을 학습할 필요 없이 자연스럽게 동작합니다.

### 결정 4: 스테이징 파일 감시 + `rhwp-studio` 비교 엔진 기반 Diff 검토
- **선택한 방식**: 기존 JSON `UnifiedOp` 기반의 `SmartDiffOverlay` 대신, 실제 파일 바이트(기준 스냅샷 vs CLI가 수정한 스테이징 파일)를 `rhwp-studio`의 비교 엔진으로 정밀 대조합니다.
- **이유**: 외부 에이전트 CLI는 어떤 순서와 방식으로든 스킬 스크립트나 XML 편집을 통해 스테이징 파일을 수정할 수 있습니다. 연산 로그(op)에 의존하지 않고 결과 문서 자체를 `rhwp-studio` 비교 엔진으로 대조하면, 누락 없는 100% 정확한 문단/표/개체 변경 내역을 사용자에게 보여줄 수 있습니다.

> [!NOTE]
> **웹 프리뷰(개발 서버)와 Tauri 데스크톱 양방향 동작 전략**:
> Tauri 데스크톱 환경에서는 Rust 백엔드가 네이티브 PTY/자식 프로세스 터미널과 파일 시스템 워처를 구동합니다. 브라우저/개발 서버 환경에서도 동일한 UI와 워크플로가 끊김 없이 검증·동작하도록 로컬 Node 백엔드 브리지(프로세스 실행 및 스트리밍 터미널 API + 스테이징 파일 워치 API)를 함께 제공합니다.

### 데이터 모델 및 상태 전략

- **Workspace Document Store (Zustand)**:
  - `session`: `originalPath`, `stagingPath`, `fileName`, `isHwpx`, `baselineBytes`(마지막 수락/열기 시점 기준본), `currentBytes`(현재 에디터 표시본), `stagedExternalBytes`(CLI가 외부에서 수정한 대기본), `undoStack`, `isDirty`.
  - `diffReview`: `status` (`idle` | `computing` | `ready`), `compareSession`(`rhwp-studio` 비교 엔진 결과: `diffItems[]`, `stats`, `currentDiffIndex`), `drawerOpen`.
  - `terminal`: `open`, `dock` (`right` | `bottom`), `panelSize`, `tabs[]` (세션 ID, CLI 프리셋, 실행 명령, 상태, 출력 버퍼), `activeTabId`, `customPresets[]` (`localStorage` 영속화).
  - `writingMemory`: 기존 로컬 저장소 기반 `memoriesIndex`, `activeMemoryIds`, 활성 메모리를 스테이징 워크스페이스의 지침 파일로 동기화한 `contextFilePath`.
  - `privacy`: `autoMaskPii`, `excludedRegions`, `activeTokenMap`(PII 가명화→복원 세션 매핑, 메모리 내 유지).
- **에디터-스토어 단방향 동기화 브리지**:
  - 최신 `rhwp-studio` 인스턴스를 감싸는 얇은 어댑터가 문서 바이트 로드, 현재 문서 내보내기(`exportHwp`/`exportHwpx`), 커서/셀 컨텍스트 조회, 선택 위치 점프, 그리고 `table:create` 중첩 표 콜백을 단일 인터페이스로 제공합니다.

### 인터랙티브 컴포넌트 및 상태 매핑

- **통합 `[표 만들기]` 핸들러**:
  - `table:create` 커맨드의 `canExecute`를 `ctx.hasDocument`로 확장합니다.
  - 실행 시 `InputHandler.getCursorPosition()`을 검사해 `parentParaIndex === undefined`이면 기존 `rhwp-studio` 본문 표 생성 로직을 수행하고, 표 셀 내부이면 현재 표의 좌표(`sec`, `parentParaIndex`, `controlIndex`, `cellInfo.row/col`)를 해석합니다.
  - HWPX인 경우 사용자가 `TableCreateDialog`에서 선택한 행·열로 `hwpx-edit` 중첩 표 삽입을 스테이징 파일에 적용한 뒤, 이전 바이트를 Undo 스택에 푸시하고 최신 `rhwp-studio` 에디터에 즉시 리로드합니다. HWP인 경우 비차단 토스트로 HWPX 형식 전환을 안내합니다.
- **내장 에이전트 CLI 터미널 패널**:
  - 탭 생성 시 선택된 프리셋 명령(`claude`, `gemini`, `codex`, 커스텀 CLI 등)과 현재 문서 스테이징 경로·스킬 경로·활성 작성 메모리 경로 환경변수를 전달해 백엔드 프로세스 세션을 엽니다.
  - 실시간 출력 스트림 렌더링, ANSI 컬러/커서 표시, 사용자 입력 전송, 인터럽트(`Ctrl+C`), 세션 재시작, 우측/하단 도킹 전환, 드래그 리사이즈, 그리고 에디터 선택 영역/메모리 프롬프트 즉시 삽입을 모두 동작하도록 연결합니다.
- **스테이징 파일 변경 감시 및 Diff 검토 패널**:
  - 문서 세션이 열리면 백엔드가 `stagingPath`의 mtime/해시를 감시해 에디터 내부 저장이 아닌 외부(CLI) 수정이 발생했을 때 변경 이벤트를 발행합니다.
  - 프런트엔드는 `baselineBytes`와 수정된 스테이징 바이트를 `rhwp-studio` 비교 엔진(`compareDocuments`)에 넘겨 `DiffItem[]`를 생성합니다.
  - 검토 패널에서 항목 클릭 시 에디터의 해당 페이지/문단/표로 포커스를 이동시키고, `[수락]` 시 수정본을 에디터에 로드하고 `baselineBytes`와 Undo 스택을 갱신하며(PII 마스킹 활성 시 자동 복원 후 반영), `[반려]` 시 `baselineBytes`로 스테이징 파일을 원복합니다.
- **작성 선호사항 메모리 & PII 보호 UI**:
  - 작성 선호사항 모달은 기존 다중 문서 파싱·직접 편집·섹션 Diff 비교·리비전 이력 기능을 유지하되, 내장 LLM API 자동 생성 대신 **"로컬 문서 추출 + CLI용 메모리 생성/정교화 프롬프트 실행"** 흐름과 직접 편집 모드를 지원해 내장 프로바이더 없이도 100% 완결 동작합니다.
  - PII 보호 패널에서는 자동 마스킹 토글, 현재 선택 영역 제외 추가/해제, 마스킹 미리보기 및 스테이징 가명화 적용/복원을 직접 제어합니다.
